4. Hôte SMTP : `MAIL_HOST` lu par `Env::get` (config/mail.php a une valeur par défaut).
5. robots.txt par une route (le fichier statique servirait le même aux deux sites).
6. La garde des faux en production couvre maintenant VIES et l'antivirus au démarrage du site réel (l'antivirus factice était seulement refusé par caisse:diagnostiquer).
7. Commandes du schéma sur la connexion `registre` : permises seulement avec `--path=database/migrations-registre` (migrate, fresh, refresh, reset, rollback) ; db:wipe toujours refusé.

### Pièges trouvés

- `postJson()` n'envoie les témoins qu'avec `withCredentials()`. `withUnencryptedCookie()` reste pour toutes les requêtes suivantes du test.
- Laravel 13 : le CSRF du groupe web est `PreventRequestForgery` ; `$middleware->replace()` ne vise que la pile globale, il faut `$middleware->web(replace: [...])` ; `shouldAddXsrfTokenCookie()` y est publique.
- Le dépôt des variables de Laravel (`Env`) est statique et immuable : il se souvient des variables lues du .env et les réécrit par-dessus celles qu'un test pose ; `Env::enablePutenv()` le refait. Une variable vide est remplacée par celle du .env : poser « (null) ».

- Une erreur fatale PHP dans un test apparaît seulement comme « Premature end of PHP process » : relancer avec `php -d display_errors=stderr vendor/bin/phpunit --filter …`.
- ReglesDuCalendrierTest refuse `::parse(`/`createFromFormat(` hors Calendrier (d'où `Calendrier::lireUnInstantUtc`), `addDays` partout, les casts `immutable_datetime` (→ `Instant::class`), toute heure sans fuseau dans un test, et `travelTo(now()…)`.
