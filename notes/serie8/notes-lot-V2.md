- Confirmation de l'inscription : tout ou rien (Sirene active + RNE représentant + adresse + courrier envoyé) ; service injoignable -> refus, lien encore valable. Limite de courriers par IP (RateLimiter).
- Page publique /code/{siren?} : SIREN + code + adresse + mot de passe (+ confirmation) ; adresse+mdp du propriétaire inscrit = même personne ; sinon reprise : ancien propriétaire -> administrateur retiré, tous les comptes retirés, nouveau propriétaire créé (identifiant), puis validation, le tout sous les verrous des registres de tous les magasins puis société puis code.
- Limites de saisie : par adresse IP (RateLimiter) ; tentatives comptées sur le code (journal) ; pas d'annulation (évite le blocage par un tiers) ; réponse identique pour SIREN inconnu / sans code / code faux.
- Nouveau courrier : un seul, au plus tôt 15 jours après le premier, annule le premier ; ensuite pièces (règle 9) + éditeur.
- Clôture : commande planifiée, 30 jours après le dernier courrier (ou la création), filtrée par société ; codes annulés, pièces effacées, démonstration fermée, propriétaire prévenu.
- Éditeur : editeur:courrier:envoyer (sans --remplacer), editeur:societe:pieces, editeur:societe:examiner (ex-valider : examen des pièces + nouveau courrier), editeur:societe:refuser (clôture motif refus). Supprimés : lever-signal, signaler, reclamation:ouvrir.
- CreerEtablissementAction : un SIRET réservé est refusé même avant la validation (SIREN unique).
- Validation : ValiderLaSocieteAction::valider(societe verrouillée, proprietaire, PreuveDeValidation::CodeDuCourrier) dans la transaction de l'appelant ; tous les magasins réels actifs mis en activité (vérifiés ou non) ; audit SocieteValidee avec la preuve.
- Transmission : plus de qualité prouvée.
- La Poste : pas de doc publique -> pas d'implémentation réelle ; dire ce que l'éditeur doit fournir (contrat API Lettre recommandée en ligne, identifiants OAuth2, spécification, bac à sable, option remise en personne).
